## Overview
Campus Mode — a college-student t-shirt/merch e-commerce store (India market) with a live custom-tee designer. Next.js 14 App Router storefront + Supabase backend (Postgres, Auth, Storage). Deployed target domain: `https://campusmode.in`.

## Tech stack
- **Next.js 14.2.5** (App Router, RSC), TypeScript, Tailwind CSS (design tokens in `globals.css` under `.teevo`).
- **Supabase** (project ref `olnscgrzhbkdiwffqmis`): Postgres + Auth (email/password + Google configured in code) + Storage (`designs` bucket, public).
- **fabric.js 5.5** (2D tee designer), **@supabase/supabase-js 2.111**, **@nextui-org/react**, **lucide-react**, framer-motion.
- Cart = React context + localStorage (`teevo-cart-v1`). No server cart.

## DB schema (Supabase, `public`)
- **orders**: id, created_at, order_no (unique), status (pending|paid|shipped|cancelled), customer_name, phone, email, address, city, state, pincode, payment_method, subtotal, shipping, total, user_id→auth.users.
- **order_items**: id, order_id→orders, product_id, name, size, color, qty, unit_price, line_total, is_custom, design_image_url, **design_spec jsonb** (meta + per-surface spec + svg/hd/preview/shirt urls).
- **profiles**: id→auth.users, email, name, phone, **role** (customer|staff|admin, default customer). Trigger `on_auth_user_created` auto-creates a profile; role read for admin.
- **addresses**: id, user_id, name, phone, address, city, state, pincode, is_default. RLS own-only.
- **reviews**: id, product_id, user_id, author_name, rating(1-5), title, body, **hidden** (moderation), unique(product_id,user_id). RLS: **select where hidden=false OR own**; **insert only if the user bought that product** (buyer-gated); own update/delete. Admin moderates via `/api/admin/reviews`. Migration `supabase/review_moderation.sql`.
- **product_variants**: id, product_id, size, color(hex), **sku** (unique = `<productId>-<size>-<colorhex>` lowercase), **stock** int. RLS public read; writes server-side. Seeded 206 rows from catalog (default stock 40; a few set to 0/3 for OOS/low demos). Read via `src/lib/stock.ts` (client) / `src/lib/stockServer.ts` (server: `checkStock`, `commitStockForOrder`).
- **orders** extra cols: `tax` (GST portion, inclusive), `stock_committed` bool (idempotent decrement guard). **3c cols:** `payment_status`, `carrier`, `tracking_no`, `tracking_url`, `shipped_at`, `delivered_at`, `cancelled_at`, `cancel_reason`, `refund_amount`, `refunded_at`, `refund_reason`, `admin_note`, `payment_ref` (Stripe pi — task 5), `stock_restored` (idempotent restore guard).
- **order_events**: id, order_id→orders (cascade), created_at, type (created|status|payment|shipping|cancel|refund|note), message, actor. Append-only audit/timeline. RLS: owner reads own; server writes (service role). Migration `supabase/order_mgmt.sql`.
- **coupons**: code(pk, UPPERCASE), type (percent|fixed|free_shipping), value, min_subtotal, max_discount, starts_at, expires_at, usage_limit, used_count, per_user_limit, active, description. RLS on, **no public read** (server-only). Atomic `redeem_coupon(code)` RPC (returns new count or −1 if exhausted). `orders.coupon_code` + `orders.discount` record redemption. Validation in `src/lib/coupons.ts`. Migration `supabase/coupons.sql`.
- **processed_webhooks**: event_id(pk), type, created_at. Stripe webhook idempotency (server-only). `orders.stripe_session_id` + `orders.payment_ref` (payment_intent) + `orders.refund_id` store Stripe ref ids only. Migration `supabase/payments.sql`.
- **contact_messages**: id, created_at, name, email, subject, message, handled. Contact-form submissions. RLS on, **no policies** → service-role (admin API) only. Migration `supabase/contact.sql`.
- **admin_audit**: id, created_at, actor, action, entity, entity_id, meta jsonb. Admin-mutation audit trail (product/coupon/category CRUD; orders use order_events). RLS on, **no policies** → service-role only. Migration `supabase/audit.sql`. Written via `src/lib/adminAudit.ts logAdminAction()`.
- **products**: id(slug pk), name, price, compare_at, rating, reviews, badge, category, sizes[], swatches[], image, images[], tone, description, active, sort. RLS public read (active). DB source once seeded (14); `catalogDb.ts` falls back to static `PRODUCTS` if empty/off. Admin CRUD via `/api/admin/products`.
- **categories**: slug(pk), label, description, sort, active. RLS public read; admin CRUD via `/api/admin/categories`. Seeded 7 from catalog. Storefront category page reads these (fallback static).
- **Storage** bucket `designs` (public read; server uploads only).
- SQL migrations saved under `supabase/*.sql` (schema.sql, profiles.sql). RLS enabled on all tables.

## Known issues / notes
- **Stripe online-payment path is code-complete but dormant** (no keys set) → couldn't be exercised live. When keys are added, test end-to-end with Stripe TEST cards and confirm the webhook marks the order paid + commits stock. The **COD fallback is fully verified**. Also: `charge.refunded` reconciliation assumes one payment_intent per order.
- Refund/stock: refund with `restock` and the Stripe gateway refund are recorded in one request; if the Stripe call succeeds but the following DB write fails (rare), the money is refunded but the order shows unrefunded until retried — the webhook `charge.refunded` path reconciles it.
- **Wishlist is localStorage-only** (`teevo-wishlist-v1`), not DB-backed → doesn't sync across devices. Fine for now; a `wishlists` table could be added later if cross-device sync is wanted.
- **Email verification / password reset** rely on Supabase Auth email templates + redirect URLs. The user should confirm the Supabase project's Site URL + redirect allowlist include the deployed domain (and localhost for testing) so the `/reset-password` and confirmation links work in production.
- **Coupon per-user limit** only enforces for logged-in users (needs `user_id`); guest orders bypass it. Total `usage_limit` is enforced atomically for everyone. Coupon codes are case-insensitive (stored uppercase).
- Refund (`/api/admin/orders/refund`) currently **records** the refund + updates `payment_status` only; the actual gateway refund call (`stripe.refunds.create` using `orders.payment_ref`) lands in **task 5**.
- ~~seed routes unauthenticated~~ FIXED in task 8 (now `requireAdmin`).
- **Rate limiting is in-memory & per-instance** (not global) — a courtesy throttle, not a hard security boundary; it also won't visibly trip under `next dev` (route modules re-evaluate per request, resetting the Map) but works in a production build / per serverless instance.
